# Signal Nine million-scale validation 001

Date: 2026-07-28

Status: **million-scale gate passed; bonus-tail tuning recommended before math
freeze**.

The official Stake Engine math SDK was asked to generate 1,000,000 deterministic
candidate outcomes per mode. Its per-batch quota allocation floors fractional
category counts, producing 999,906 outcomes per mode. This 94-outcome shortfall
is 0.0094% and does not invalidate the million-scale evidence, but all counts in
this report use the actual value.

The official Rust optimizer produced ten integer weight sets per mode.
Measurements below use the highest-scored pair and were verified before the
publish tables were restored to unit weights.

## Generation and validation

- Generation completed in 790.15 seconds with six simulation workers.
- Books and lookup tables contain exactly 999,906 entries per mode.
- The complete books were streamed through the structural reviewer.
- Book SHA-256, payout-array hashes, lookup payouts, and sidecar counts match.
- Simulation and event indexes are contiguous.
- Every book ends in `finalWin`.
- Every capped book has a matching `wincap`.
- Every free-game reveal has Core in the center.
- Amplifier values never exceed 9×.

The reviewer was converted from whole-pool loading to bounded-memory streaming
after the original implementation encountered memory pressure at this scale.
Two focused regression tests cover exact summaries and book/LUT length
mismatches.

## Gate decision

The million-scale run passes the recorded mechanical and working-limit checks:

- both modes remain at 96.50% RTP;
- base hit and natural feature rates remain on target;
- normalized volatility remains within range;
- maximum win remains represented and attainable;
- compressed files and event counts remain within platform limits;
- payout diversity improved without event-sequence growth;
- ETL and CVaR remain below the working 3-star limits.

However, bonus CVaR progressed from `613.510` at 10,000 outcomes to `677.512`
at 100,000 and `768.593` at 999,906. The current value is only `31.407` below
the working limit of `800`.

This is technically a pass, but the margin is too narrow for a comfortable math
freeze. A small optimizer or bonus-distribution change could cross the limit.

## Publish-path state

The official optimizer automatically promoted its highest-scored trial while it
ran. After verification, both publish lookup tables were restored from the
untouched unit-weight source tables and generated configs were refreshed.

No experimental optimizer weights are currently promoted.

## Recommended next work

Before freezing production math:

1. reduce the bonus tail so CVaR has meaningful headroom below `800`;
2. re-optimize against the existing 999,906-book pool;
3. re-run official and independent exact verification;
4. select and review final integer lookup weights explicitly;
5. only then assemble the upload bundle and freeze displayed RTP/math values.

The generated outcome pool is sufficiently large for this tuning step; another
full regeneration is not required unless the game mechanics or outcome
generation distributions change.
